# MCSManager 服务器运维

`astrbot_plugin_mcsm_ops` v0.2.3，适用于 AstrBot `>=4.16,<5`、OneBot v11 / aiocqhttp、MCSManager 10.22.1 和 NeoForge Minecraft 服务端。

通过面板 REST API 管理多个实例：查询状态、玩家、TPS、控制台日志，执行命令、启停、管理白名单，并向绑定群推送崩溃告警。提供受限的 LLM 只读工具。**不做聊天互通**；聊天互通继续由 mcqq 与鹊桥模组负责。

## 面板侧准备

1. 在 MCSManager 面板设置中开启 **API 密钥**功能。
2. 新建专用普通用户，在用户/权限管理中只给该用户分配所有目标实例及所需操作权限；不要使用面板超级管理员密钥。
3. 登录该专用用户，在「用户设置」生成 API 密钥，填入插件 `api_key`。403 通常表示 API 密钥功能未开启、密钥无效或用户无实例权限。
4. 打开每个目标实例的控制台/管理页，在浏览器地址栏 URL 中查看 `daemonId`（节点 ID）与 `uuid`（实例 UUID）。若页面路由未直接展示它们，可在浏览器开发者工具 Network 中查看该实例 `/api/instance` 请求的 `daemonId` 与 `uuid` 查询参数。分别填入对应实例的 `daemon_id`、`instance_uuid`，不要混用实例 UUID 和节点 ID。
5. `panel_url` 填面板基址，例如 `https://panel.example.com:23333`，不带 `/api` 或末尾斜杠。建议使用 HTTPS，并限制面板的网络访问范围。

API 密钥只通过 `x-request-api-key` 请求头发送，不放入 URL 查询参数。插件会从输出和错误日志中移除配置密钥；仍不要把密钥发送到聊天或写入 Minecraft 控制台。HTTP 重定向不会被自动跟随，请直接填写最终面板地址。

## 安装与配置

将插件目录安装到 AstrBot 插件目录，通过插件管理安装 `requirements.txt` 中的 `aiohttp>=3.9`，填写 `panel_url`、`api_key`，并在 `instances` 中添加至少一个有效实例，保存并重载插件。管理员身份由 AstrBot 管理员配置决定，不按 Minecraft 玩家名判断。无效实例会被跳过并记录警告。

### 全局配置

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `panel_url` / `api_key` | 空 | 面板地址与密钥；缺失或没有有效实例时不发请求 |
| `instances` | `[]` | 模板列表，选择「实例」模板添加条目，按别名显示；详见下表 |
| `allowed_platforms` | `["aiocqhttp"]` | 按 `event.get_platform_name()` 放行指令；其余平台静默忽略 |
| `request_timeout_seconds` | `10` | 单次请求超时秒数 |
| `command_wait_seconds` | `1.5` | 命令回读等待秒数，实际至少 `0.6` |
| `log_fetch_kb` | `64` | 每次读取的日志 KB 数 |
| `log_default_lines` / `log_max_lines` | `20` / `100` | 日志缺省行数和上限 |
| `log_mask_ip` | `true` | 日志与命令结果中的 IPv4 脱敏为 `*.*.*.*`、IPv6 脱敏为 `*:*` |
| `list_command` | `list` | 在线玩家查询命令 |
| `list_regex` | 见配置面板 | 组 1 在线数，组 2 上限，组 3 逗号分隔玩家名 |
| `op_wait_seconds` | `240` | 后台启停监测最长秒数 |
| `alert_interval_seconds` | `30` | 告警轮询间隔秒数，实际至少 `10` |
| `platform_id` | 空 | QQ 平台适配器的 ID，用于告警推送；留空时在发送时自动选择唯一的 aiocqhttp 适配器 |
| `llm_allowed_commands` | `["list", "neoforge tps", "spark tps", "spark health"]` | LLM 只读命令白名单；不得加入有副作用的命令 |

### 每个实例的配置

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `alias` | 空 | 必填实例别名，例如 `生存`；不得包含空白或控制字符，不得为 `all`，忽略大小写后必须唯一；两个条目不能指向同一个实例 |
| `daemon_id` | 空 | 必填节点 ID（daemonId） |
| `instance_uuid` | 空 | 必填实例 UUID |
| `groups` | `[]` | 绑定的 QQ 群号列表；同一个群可绑定多个实例；未绑定任何实例的群不能使用 `/mcs` |
| `tps_command` | `neoforge tps` | Paper 用 `tps`；留空则不查询 TPS |
| `tps_regex` | 见配置面板，与 `console.py` 默认值一致 | 组 1 TPS，组 2 MSPT，默认只匹配 NeoForge 的 Overall 行；留空使用默认正则 |
| `alert_enabled` | `true` | 是否轮询该实例的崩溃与连接状态；还需至少绑定一个群才会轮询 |

例如创建「生存」「创造」两个实例，将同一个 QQ 群号填入两者的 `groups`，该群就能查询这两个实例；分别填写各自的节点 ID、实例 UUID 和 TPS 配置。Paper 等服务端的 TPS 输出格式不同，需要同时调整该实例的 `tps_regex`；自定义正则仍应从行首锚定，避免将玩家聊天识别为服务器输出。

**不要把 mcqq/游戏来源适配器加入 `allowed_platforms`**：游戏内聊天默认不能调用 `/mcs`。游戏平台 `minecraft` 仅通过 LLM 只读工具查询，可见**绑定了至少一个群**的实例（未绑定群的实例只有管理员私聊可见），不获得控制台任意命令或启停权限。

### 会话与别名范围

- QQ 群内只可访问该群绑定的实例，**管理员也不例外**；未绑定的群中普通用户不获回复，管理员收到「本群未绑定实例」。
- 管理员私聊可访问全部实例；非管理员私聊没有可见实例。
- 只有一个可见实例时可省略别名。多个可见实例时，`status`、`list` 不带别名返回逐实例摘要；其他操作必须指定别名。别名匹配不区分大小写。
- `all` 只用于白名单 add/remove，表示**当前会话可见的全部实例**，不绕过群绑定范围。

安全提示：

- 管理员权限只决定谁能执行 `log` / `cmd` 等管理操作，**不决定谁能看到输出**。日志里可能有私聊、坐标、模组报错中的连接串等，建议只在私聊或管理群里使用这两条指令。
- `/mcs cmd 生存 stop` 等价于直接停服，不经过 `/mcs stop 生存 确认` 的确认与启停并发限制。
- 控制台命令会出现在面板与反向代理的访问日志里（它是 GET 查询参数），不要用 `cmd` 发送密码类内容。
- `panel_url` 请用 HTTPS；用 `http://` 时 API 密钥会在网络上明文传输。

## 指令

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/mcs status [别名]` | 所有人 | 单实例：名称、状态、在线数、版本、CPU、内存、运行时长，运行中补充 TPS/MSPT；多实例不带别名：每个实例一行状态与在线数，只读 detail，不发控制台命令 |
| `/mcs list [别名]` | 所有人 | 单实例：命令回读在线玩家，未运行时提示；多实例不带别名：每个实例一行在线数，只读 detail，不执行 list |
| `/mcs log [别名] [行数] [关键词…]` | 管理员 | 清洗后按不区分大小写的子串过滤，再取最后 N 行；aiocqhttp 合并转发 |
| `/mcs cmd [别名] <命令>` | 管理员 | 去掉开头一个 `/`，拒绝换行与控制字符；最多返回 30 行新增输出 |
| `/mcs start [别名]` | 管理员 | 启动实例，立即确认并在后台报告完成 |
| `/mcs stop [别名] 确认` | 管理员 | 停止实例，在线玩家会掉线；确认提示包含别名 |
| `/mcs restart [别名] 确认` | 管理员 | 重启实例，在线玩家会掉线；确认提示包含别名 |
| `/mcs wl add [别名\|all] <玩家名>` | 管理员 | 对所选实例执行 `whitelist add <玩家名>` |
| `/mcs wl remove [别名\|all] <玩家名>` | 管理员 | 对所选实例执行 `whitelist remove <玩家名>` |
| `/mcs wl list [别名]` | 管理员 | 对单个实例执行 `whitelist list`，不支持 all |

示例：`/mcs log 生存 40 player joined` 将 `player joined` 整体作为关键词；`/mcs log 生存 ERROR` 使用默认行数。别名后的首个 token 为正整数时才解释为行数；行数不得超过配置上限。`/mcs cmd 创造 say  hi` 保留命令参数中的双空格。多个实例摘要中，某个实例获取失败不会影响其他实例。

白名单玩家名必须恰好一个参数，且为 3–16 位字母、数字或下划线；非法玩家名不会发送任何命令。`/mcs wl add all Steve` 会向当前会话可见的每个实例添加 Steve。每个实例单独返回结果（最多 10 行）；未运行的实例显示「未运行」，单个失败不影响其他实例，无输出时显示「命令已发送，无输出」。

## 崩溃与连接告警

- 插件加载后后台轮询；仅检查 `alert_enabled=true` 且 `groups` 非空的实例。首次成功读取仅建立基线，不把插件加载前的停服当作崩溃。
- 观察到「运行中 → 已停止」时，读取日志并清洗，在最近一次启动完成（`Done (`）之后的日志里查找从行首锚定的 `Stopping the server` 服务器输出行（不区分大小写，玩家聊天里打这句话无效）。有则视为正常关服，不推送；没有则向该实例每个绑定群发送意外停止摘要，附本地时间和 `/mcs log 别名` 提示。
- MCSManager 的 `config.lastDatetime` 变化、当前处于启动中或运行中、且此前未观察到停止时，提示「不是通过 /mcs，可能是崩溃后被面板自动重启」。这是基于状态与启动时间的推断，不保证能区分所有外部重启原因。
- 已发崩溃告警的实例恢复运行时推送恢复消息；自动重启告警的同一轮不会立刻再发恢复消息。
- 连续 3 次无法读取状态时仅推送一次失联提示；重新读到状态后推送恢复连接。单个实例轮询异常不会终止其他实例的监测。
- `/mcs` 发起的启停操作期间不发崩溃告警，操作结束后重新建立基线。
- 告警**只发摘要，不附日志原文**，仍会清除 API 密钥。`platform_id` 填适配器 ID，不是平台名称；留空时只有恰好一个 aiocqhttp 适配器才能自动选择。没有或存在多个适配器时不发送，插件每次加载期间只记录一次要求配置 `platform_id` 的错误。

## LLM 只读工具

| 工具 | 参数 | 用途 |
| --- | --- | --- |
| `mc_server_status` | `instance=""` | 查询状态、在线人数与 TPS；留空查询当前会话可见的全部实例，每实例一段 |
| `mc_online_players` | `instance=""` | 使用 `list_command` 查询名单；多个可见实例时必须指定别名 |
| `mc_run_readonly_command` | `command`、`instance=""` | 只执行 `llm_allowed_commands` 允许的完整命令；多个可见实例时必须指定别名 |

- 工具仅允许 `allowed_platforms` 中的平台，以及游戏平台 `minecraft`。QQ 群与私聊仍遵循上述可见范围；游戏平台可查询绑定了群的实例。没有可见实例时返回「当前会话没有可查询的服务器」。
- 只读命令白名单是**完整匹配**，忽略大小写、开头一个 `/` 和重复空白，但不允许追加参数；例如 `/Spark TPS` 匹配配置的 `spark tps`，`spark tps extra` 不匹配。真正发送的是配置中的规范命令，不是 LLM 原文。需要参数时，应把完整命令写入白名单。
- **白名单命令的输出无法保证干净**：插件会过滤聊天、玩家执行的命令、进出服、成就和常见死亡信息，但这是黑名单，模组自定义的聊天格式或少见的死亡信息仍可能混进来（例如带着玩家改名物品的文字），并被 LLM 转述到其他群。查名单和 TPS 只返回解析结果，不受影响。介意的话把 `llm_allowed_commands` 设为空列表，即可关闭白名单命令。
- **不要加入 `spark profiler`、`op`、`stop` 等命令**：profiler 会启动分析任务、产生负载或改变服务端状态，并非只读查询；白名单是管理员的安全边界，插件不会自动把任意命令变成只读。
- 状态中的 TPS、在线名单和白名单只读命令使用相同缓存与锁规则：按实例及实际命令缓存 30 秒；同实例命令锁被占用时立即返回繁忙，不排队；未运行时不发命令。缓存可能使查询结果有最多约 30 秒延迟。
- 工具返回字符串，不直接发送群消息。命令回读窗口里会混入其他玩家的聊天和进服记录，工具会去掉聊天、表情动作、进出服与登录行，**无论 `log_mask_ip` 如何都隐藏 IP**，保留最新的 2000 字，整个返回值清除 API 密钥；查名单或 TPS 解析失败时只返回「未能解析在线列表」「TPS：获取失败」，不返回原始输出。没有任何能执行任意命令或启停的 LLM 工具。

## 输出与启停语义

- 面板发送命令的接口只返回成功标志，**不直接返回命令输出**。插件按实例分别持锁串行执行「读日志 → 发命令 → 等待 → 再读日志」，以之前最后 3 个非空行的最后一次连续出现位置为锚点；不同实例互不占用同一把锁。
- 查玩家/TPS 时第一次没有匹配结果会再等一次并重读。TPS 获取失败只显示 `TPS：获取失败`，不影响其他状态字段。已有命令在回读时，`status` 的 TPS 与 `list` 直接回复「繁忙」而不排队，避免群成员刷指令刷爆控制台。
- 默认正则从行首锚定，文字前只允许出现日志前缀 `[...] [...]: `，所以只匹配服务器自身输出；玩家在聊天里打出同样的文字（哪怕带上 `]: There are ...`）也不会被当成结果。自定义正则时请保持这种锚定。
- 普通日志与命令输出单行最多 500 字符、总输出最多 4000 字符，避免长堆栈超出 QQ 消息上限。密钥与 IP 脱敏在截断之前逐行完成，截断不会留下半截密钥或 IP。
- daemon 约每 500ms 刷盘，日志超过 512 KiB 会删除重建。锚点丢失时回退到最近 50 行，`cmd` 提示「日志已轮转，结果可能不完整」。若日志大量滚动或外部也在执行命令，回读不能保证只含本条命令输出。
- 日志去除 ANSI、`§` 颜色码、回车、空行和行尾空白。IP 脱敏不等于隐私审查：玩家名、聊天内容等仍可能出现，管理员应控制转发范围。
- 每个实例同时只允许一个启停操作；每 3 秒查一次，启动/重启目标为运行中，停止目标为已停止。重启会经过「停止中 → 已停止 → 启动中 → 运行中」，所以重启要先观察到离开运行中，再回到运行中才算完成；只有看到「启动中」之后又回到已停止，才报告启动失败。完成、失败、超时均带别名发送到原会话。重载/卸载插件会取消任务并关闭 HTTP 会话，不会停止 Minecraft 实例。

## 本地测试

在 AstrBot 仓库根目录执行（先 `uv sync` 装好 AstrBot 自身依赖）：

```bash
.venv/bin/python -m pytest data/plugins/astrbot_plugin_mcsm_ops/tests -q
```

测试不启动 AstrBot，也不连接面板。
