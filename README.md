# MCSManager 服务器运维

`astrbot_plugin_mcsm_ops` v0.1.0，适用于 AstrBot `>=4.16,<5`、OneBot v11 / aiocqhttp、MCSManager 10.22.1 和 NeoForge Minecraft 服务端。

只通过面板 REST API 查询状态、玩家、TPS、控制台日志及执行命令、启停实例。**不做聊天互通**；聊天互通继续由 mcqq 与鹊桥模组负责。

## 面板侧准备

1. 在 MCSManager 面板设置中开启 **API 密钥**功能。
2. 新建专用普通用户，在用户/权限管理中只给该用户分配目标实例及所需操作权限；不要使用面板超级管理员密钥。
3. 登录该专用用户，在「用户设置」生成 API 密钥，填入插件 `api_key`。403 通常表示 API 密钥功能未开启、密钥无效或用户无实例权限。
4. 打开目标实例的控制台/管理页，在浏览器地址栏 URL 中查看 `daemonId`（节点 ID）与 `uuid`（实例 UUID）。若页面路由未直接展示它们，可在浏览器开发者工具 Network 中查看该实例 `/api/instance` 请求的 `daemonId` 与 `uuid` 查询参数。分别填入 `daemon_id`、`instance_uuid`，不要混用实例 UUID 和节点 ID。
5. `panel_url` 填面板基址，例如 `https://panel.example.com:23333`，不带 `/api` 或末尾斜杠。建议使用 HTTPS，并限制面板的网络访问范围。

API 密钥只通过 `x-request-api-key` 请求头发送，不放入 URL 查询参数。插件会从输出和错误日志中移除配置密钥；仍不要把密钥发送到聊天或写入 Minecraft 控制台。HTTP 重定向不会被自动跟随，请直接填写最终面板地址。

## 安装与配置

将插件目录安装到 AstrBot 插件目录，通过插件管理安装 `requirements.txt` 中的 `aiohttp>=3.9`，填写上述四个必填项，保存并重载插件。管理员身份由 AstrBot 管理员配置决定，不按 Minecraft 玩家名判断。

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `panel_url` / `api_key` / `daemon_id` / `instance_uuid` | 空 | 面板地址、密钥、节点、实例；缺失时不发请求 |
| `allowed_platforms` | `["aiocqhttp"]` | 按 `event.get_platform_name()` 放行；其余平台静默忽略 |
| `request_timeout_seconds` | `10` | 单次请求超时秒数 |
| `command_wait_seconds` | `1.5` | 命令回读等待秒数，实际至少 `0.6` |
| `log_fetch_kb` | `64` | 每次读取的日志 KB 数 |
| `log_default_lines` / `log_max_lines` | `20` / `100` | 日志缺省行数和上限 |
| `log_mask_ip` | `true` | 日志与命令结果中的 IPv4 脱敏为 `*.*.*.*`、IPv6 脱敏为 `*:*` |
| `list_command` | `list` | 在线玩家查询命令 |
| `list_regex` | 见配置面板 | 组 1 在线数，组 2 上限，组 3 逗号分隔玩家名 |
| `tps_command` | `neoforge tps` | 留空禁用状态中的 TPS 查询 |
| `tps_regex` | 见配置面板 | 组 1 TPS，组 2 MSPT；只匹配 Overall 行 |
| `op_wait_seconds` | `240` | 后台启停监测最长秒数 |

**不要把 mcqq/游戏来源适配器加入 `allowed_platforms`**：游戏内聊天经 mcqq 会变成 AstrBot 事件，默认仅 aiocqhttp 可以调用指令，包括公开查询。

安全提示：

- 管理员权限只决定谁能执行 `log` / `cmd`，**不决定谁能看到输出**。日志里可能有私聊、坐标、模组报错中的连接串等，建议只在私聊或管理群里使用这两条指令。
- `/mcs cmd stop` 等价于直接停服，不经过 `/mcs stop 确认` 的确认与并发限制。
- 控制台命令会出现在面板与反向代理的访问日志里（它是 GET 查询参数），不要用 `cmd` 发送密码类内容。
- `panel_url` 请用 HTTPS；用 `http://` 时 API 密钥会在网络上明文传输。

## 指令

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/mcs status` | 所有人 | 名称、状态、在线数、版本、CPU、内存、运行时长；运行中补充 TPS/MSPT |
| `/mcs list` | 所有人 | 命令回读在线玩家；实例不在运行时提示 |
| `/mcs log [行数] [关键词…]` | 管理员 | 清洗后按不区分大小写的子串过滤，再取最后 N 行；aiocqhttp 合并转发 |
| `/mcs cmd <命令>` | 管理员 | 去掉开头一个 `/`，拒绝换行与控制字符；最多返回 30 行新增输出 |
| `/mcs start` | 管理员 | 启动实例，立即确认并在后台报告完成 |
| `/mcs stop 确认` | 管理员 | 停止实例，在线玩家会掉线 |
| `/mcs restart 确认` | 管理员 | 重启实例，在线玩家会掉线 |

示例：`/mcs log 40 player joined` 将 `player joined` 整体作为关键词；`/mcs log ERROR` 使用默认行数。首个 token 为正整数时才解释为行数；行数不得超过配置上限。命令如 `/mcs cmd say 服务器即将维护` 会保持原始参数内的空格。

## 输出与启停语义

- 面板发送命令的接口只返回成功标志，**不直接返回命令输出**。插件用同一把锁串行执行「读日志 → 发命令 → 等待 → 再读日志」，以之前最后 3 个非空行的最后一次连续出现位置为锚点。
- 查玩家/TPS 时第一次没有匹配结果会再等一次并重读。TPS 获取失败只显示 `TPS：获取失败`，不影响其他状态字段。已有命令在回读时，`status` 的 TPS 与 `list` 直接回复「繁忙」而不排队，避免群成员刷指令刷爆控制台。
- 默认正则从行首锚定，文字前只允许出现日志前缀 `[...] [...]: `，所以只匹配服务器自身输出；玩家在聊天里打出同样的文字（哪怕带上 `]: There are ...`）也不会被当成结果。自定义正则时请保持这种锚定。
- 单行最多 500 字符、总输出最多 4000 字符，避免长堆栈超出 QQ 消息上限。密钥与 IP 脱敏在截断之前逐行完成，截断不会留下半截密钥或 IP。
- daemon 约每 500ms 刷盘，日志超过 512 KiB 会删除重建。锚点丢失时回退到最近 50 行，`cmd` 提示「日志已轮转，结果可能不完整」。若日志大量滚动或外部也在执行命令，回读不能保证只含本条命令输出。
- 日志去除 ANSI、`§` 颜色码、回车、空行和行尾空白。IP 脱敏不等于隐私审查：玩家名、聊天内容等仍可能出现，管理员应控制转发范围。
- 同时只允许一个启停操作；每 3 秒查一次，启动/重启目标为运行中，停止目标为已停止。重启会经过「停止中 → 已停止 → 启动中 → 运行中」，所以重启要先观察到离开运行中，再回到运行中才算完成；只有看到「启动中」之后又回到已停止，才报告启动失败。完成、失败、超时均发送到原会话。重载/卸载插件会取消任务并关闭 HTTP 会话，不会停止 Minecraft 实例。

## 本地测试

在 AstrBot 仓库根目录执行（先 `uv sync` 装好 AstrBot 自身依赖）：

```bash
.venv/bin/python -m pytest data/plugins/astrbot_plugin_mcsm_ops/tests -q
```

测试不启动 AstrBot，也不连接面板。
